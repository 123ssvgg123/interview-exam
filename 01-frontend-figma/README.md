# Upload Your Resume — Figma 还原页

前端实习笔试题交付物：按设计稿还原「Finish! / Upload Your Resume / Upload file」这一步的上传页面，并把拖拽上传做成真实可用的交互。

纯静态实现，零依赖、零构建，离线可直接打开。

---

## 一、如何运行

**方式 A：直接打开**

双击 `index.html`（或拖进浏览器）即可。CSS / JS 都是相对路径外链，`file://` 下功能完整（含拖拽、文件校验、键盘操作）。

**方式 B：起本地静态服务**（更接近真实环境，推荐用于录屏 / 演示）

```bash
cd 01-frontend-figma
python -m http.server 8000
# 浏览器打开 http://localhost:8000
```

浏览器要求：Chrome / Edge / Firefox / Safari 近两年版本（用到 `Element.classList.toggle` 第二参数、`clamp()`、`inset()` 等现代特性）。

## 四、交互清单

**选择文件**

1. 点击虚线区域任意位置 → 打开系统文件选择框（`<label for>` + `input[type=file]` 原生关联）。
2. 拖拽区获得焦点时按 `Enter` / `Space` → 同样打开选择框（`keydown` 拦截 + `input.click()`）。
3. 拖入文件：`dragenter/dragover` 时边框由虚线变实线、颜色转主蓝、底色加深；`dragleave` 还原；`drop` 后读取 `dataTransfer.files`。
4. 拖到页面其它位置不会被浏览器直接打开文件（`window` 级 `dragover/drop` 兜底 `preventDefault`）。
5. 拖拽进出用计数器 `dragDepth` 处理子元素 `dragleave` 抖动问题。

**已选状态**

6. 选中 / 拖入后，虚线框内换成文件图标 + 文件名 + 文件大小 + 「已就绪，点击可重新选择」，提示文案隐藏。
7. 状态行同步显示「已选择 xxx.pdf（2.0 MB），确认无误后点击 Finish。」（绿色）。

**校验（页面内提示，不用 alert）**

8. 扩展名白名单：`.pdf/.doc/.docx/.png/.jpg/.jpeg`，其它类型 → 虚线框变红、状态行红色报错。
9. 扩展名合法但 MIME 可疑（如把 .zip 改名成 .pdf）→ 提示「文件内容与扩展名不匹配」。
10. 超过 10 MB、空文件、无扩展名、多选（取第一个并提示）各有独立文案。

**按钮**

11. 两个按钮都有 `hover` / `active`（`translateY(1px)`）/ `focus-visible` 反馈。
12. 未选文件点 Finish：不阻塞、不弹窗 —— 状态行红色提示 + 虚线框抖动动画 + 焦点自动移到拖拽区。
13. 已选文件点 Finish：进度条推进（三个点全部变勾）、按钮文案变 `Submitted`、状态行绿色「已提交…」。
14. Last step：进度条回到第 2 步，提示「已回到上一步」，Finish 文案复位。

**无障碍**

15. 语义化：`header` + `main` + `section` + `aside`（插画）；标题层级 `h1` → `h2`。
16. `label` 与 `input[type=file]` 显式关联，`input` 视觉隐藏但保留在可访问树中；拖拽区 `role="button"` + `tabindex="0"` + `aria-describedby`。
17. 状态行 `role="status"` + `aria-live="polite"`，报错 / 成功都会被读屏播报。
18. 进度点带 `aria-current="step"` 与 `visually-hidden` 文字说明。
19. 全站可见 `:focus-visible` 描边；首屏提供「Skip to the upload field」跳过链接。

## 五、响应式断点

| 断点 | 变化 |
| --- | --- |
| `> 1400px` | 桌面两栏，全部尺寸按 `vw` 等比缩放（1920 下与设计稿比例一致） |
| `≤ 1400px` | 副标题最大宽度略放宽，避免过早换行 |
| `≤ 900px` | 改上下结构：文案 + 插画在上、卡片在下，卡片宽度 100%；拖拽区改为 `min-height: 220px` 自适应；字号切固定 px；按钮等分宽度 |
| `≤ 560px` | 按钮纵向排布（`flex-direction: column`，等宽 100%）；拖拽区 190px；卡片内边距收紧到 18px；标题降到 22–28px |

另外 `prefers-reduced-motion: reduce` 下关闭抖动与过渡动画。

## 六、已知差异与取舍

1. **两级标题字号与需求文档不一致，按截图还原。** 需求写的是「Finish! 约 18px、Upload Your Resume 约 28px」，但在 1480 宽的参考截图上，两行的大写字母高度分别是 ≈21.7px 与 ≈25px，反推字号约 30px 与 34.7px（比例 0.87），两者视觉上接近而非「小标签 + 大标题」。本实现以截图为准取 1.98vw / 2.19vw（1920 下 38 / 42px），否则整页比例会和参考图明显对不上。如需严格按 18/28 出图，把两个 `--fs-kicker` / `--fs-title` token 改掉即可，其余布局不受影响。
2. **插画是自绘 SVG，不是像素级复刻。** 按参考图的构图重画：左侧卷尾蓝猫（坐姿、深色描边）、猫头上方白色四孔气泡、蓝色描边手机、深色四白点气泡、右侧羽毛笔，尺寸与占位（约 39vw，右侧与卡片留 60px 空隙）对齐原稿。猫的表情、羽毛的羽枝数量、手机屏幕里的列表条数是简化的，体量与配色保持一致。
3. **多了一条格式说明和状态行。** 设计稿虚线框和按钮之间是纯留白；功能要求「页内提示」，所以在这段留白里放了「PDF, DOC, DOCX, PNG, JPG, JPEG · max 10 MB」和 `aria-live` 状态行（未操作时不可见文字，占位高度固定，避免布局跳动）。这是刻意的功能补充。
4. **进度点状态。** 原稿三个点都是「蓝底 + 白色小符号」，本实现做成：前两点对勾（已完成）、第三点白点（当前），提交后第三点也变对勾。属于把静态图解释成可交互的状态机，视觉仍与原稿一致。
5. **换行位置字体差异。** 设计稿字体应为 Inter，本页字体栈首位是 `Inter`，但多数 Windows 环境没装，会回退到 Segoe UI / 微软雅黑，字宽略窄，副标题换行点可能在 ±1 个词内浮动（已用 `max-width` 控制在「…optimize, you / can upload your resume in this step」附近）。
6. **移动端超过一屏。** 390×844 下整页高度约 950px，需要滚动（正常页面行为），截图 capture 的是首屏。
7. **不做真实上传。** 纯前端题目，点击 Finish 只做前端状态流转（进度 + 成功提示），没有 XHR / 后端。
